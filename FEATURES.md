## Roles & tiers at a glance

| Role | How assigned | Key capabilities |
|---|---|---|
| **Public visitor** | unauthenticated | Marketing site, register/login, accept invite |
| **Teacher — Free** | default on signup | Limited grading/presentations, no docs/RAG/email |
| **Teacher — Pro** | paid (T-Bank) | Unlimited, document upload, RAG, email drafts, full history |
| **Institution member** | invite or email-domain auto-join | Inherits full institution entitlements + shared criteria |
| **Institution admin** | platform admin sets the first (`admin` on the institution root); an institution admin can then grant `admin`-on-root to peers via Структура | Manage own institution (teachers, invites, criteria, usage, audit, org tree + roles) |
| **Platform admin** | set in DB | Full platform: teachers, institutions, templates, billing, feedback, errors |

**Unit-scoped roles** (`admin` / `head` / `viewer`, granted on any org unit, cascade down the tree): `admin` on the institution root = institution admin. `head`/`admin` on a `governance`/`admin_office` unit grants institution-wide programme access by unit type; on any other unit it scopes to that unit's subtree. The grant UI warns before an institution-wide grant. `viewer` is recorded but not yet consumed by any surface (labelled as such in the UI).

Entitlements are computed as the **stronger of** the teacher's own tier and their
institution's tier (`backend/src/middleware/authenticate.ts`).

## Teacher — Free ✅

**Grading**
- AI grading via DeepSeek — pick one or more criteria at grading time + per-criterion weights (sum to 100%), or grade holistically with no criteria. 5-point Russian scale (5/4/3/2), per-criterion breakdown, strengths, improvements. When criteria are used, the overall score is the deterministic weighted sum of the per-criterion scores (not a freehand model total), and the 5/4/3/2 letter is always derived from that final score against one shared set of bands — score, letter and label can no longer disagree with each other. The final score is also passed through a per-course/teacher/institution **calibration map** — a monotone correction learned from that scope's own history of AI scores vs. the teacher's final approved scores — that quietly corrects systematic grading bias (running hot/cold) before the teacher ever sees the number; falls back to the raw score whenever a scope has no fitted calibration yet
- Teacher review + approve flow (AI never final; approval feeds RAG)
- **Editable strengths/improvements lists on approval** — teacher can add/remove/edit bullets before approving; teacher-edited improvements drive the revision check on the next resubmission
- **Assignment revisions** — when a student resubmits an improved version, link from the past-work detail modal («↻ Оценить переработку») → AI sees v1's feedback as context and returns a per-point check (`addressed` / `partial` / `not_addressed`) with notes; revision badge + colour-coded list on the result
- **«За семестр» trajectory** — when a submission has a known student, both the live grading result panel and the История detail view show their last 3 grades (score/grade history) plus **per-criterion movement** vs. the most recent prior occurrence of each criterion (e.g. «72 → 85 (+13)»), scoped to the current course. Pure history lookup, no AI calls
- STEM / calculation mode (reasoning model + optional reference solution)
- **Async grading jobs** — every проверка runs as a durable pg-boss job (202 + poll, same machinery as ВКР reviews): no HTTP timeout can kill a slow reasoner chain, and an in-flight проверка survives page refresh (resume banner) and PM2 restarts
- **Задание и контекст** — optional free-text field (collapsed by default) where the teacher pastes the assignment brief and/or situational context (e.g. «ознакомительная практика, проводилась в аудитории»); model is instructed to grade strictly within this scope instead of guessing the assignment from the submission alone. Applies to the primary grade and to all «Тщательная проверка» ensemble samples
- Grading history / **Журнал** (search by student/group, subject + status filters, pagination)
- Revisit any past grade (read-only detail modal, incl. ВКР chapter review + revision check)
- Moodle-compatible **CSV grade export**
- Watermark on output (free tier only)
- Limits: 20 grades/mo, 3 presentations/mo, 3 topic generations/mo, 3 quizzes/mo, 3 task sets/mo, 3 subjects, 15 criteria, 30-day history

**Topics** — AI topic generator for research/practicals: student level + field + interests + practice site → level-appropriate, valuable topics (with rationale, scope, novelty). Yandex Search grounding. Optional student attachment (name + group, autocomplete from existing students) for later lookup. Free: 3/mo, Pro: unlimited
**Subjects (formerly «Курсы»)** — CRUD, level, syllabus text/upload. Renamed in UI per Russian-academic vocab («курс» = year of study; «предмет» = subject). URL `/courses` and DB `course_id` unchanged
**Criteria** — library of reusable criteria (name + description + optional subject), start from global templates. **Уровни оценки (optional)** — describe what merits a 5/4/3/2 for this specific criterion; ИСПУМ then scores against those descriptions instead of inferring them from the criterion's name, and tells the student which level they reached and what's missing to reach the next. Fill in as few or as many levels as you like; the descriptions are snapshotted with each grading, so editing them later never rewrites past results. Selected at grading time with per-criterion weights and a live sum-to-100 check. **«Улучшить» AI-assist** on the description field rewrites a rough draft into clearer grading-prompt input — teacher accepts/rejects the suggestion, nothing is overwritten silently. **Share to org unit**: a teacher can share their own criterion/rubric up their own chain (department → faculty → whole institution) via a picker on the Критерии/Рубрики pages — no institution-admin step required. Visibility follows the org tree (§7): a teacher sees a shared item when their own primary unit sits at-or-under the unit it was shared with. Free: 5/mo, Pro: unlimited
**Students** — auto-collected roster from graded work, per-student grade-over-time chart, groups. Student profile shows **rework analytics**: first submissions vs доработки, median time between versions, average score progress across versions, «Работа с замечаниями» panel (how many feedback points the student fixed / partially fixed / ignored, from the AI revision check), works list grouped into revision chains with «версия N» badges and score deltas. **«По группе» cohort tab** — overall grade-distribution histogram, per-group breakdown (count + average score), top-3 weakest criteria across the cohort, and «Требуют внимания» — students whose recent grades dropped meaningfully vs. their own prior average, click-through to their profile. Pure aggregation, no AI calls
**Учебный план и РПД — суите** 🚧 — one page (`/curriculum`), three tabs (КНИТУ curriculum-intelligence; teacher-scoped pending a first-class учебный план entity; see `docs/KNITU-roadmap.md`):
- **Дублирование тем** (A3) — select ≥2 disciplines → extracts each discipline's topics, compares them semantically across disciplines, flags duplicated / partially-overlapping / adjacent topics with a recommendation
- **Соответствие РПД компетенциям** (A2) — select a discipline → auto-extracts the ОПК/ПК/УК competencies + goals declared in its РПД → scores how well the content covers each (обеспечена / частично / не обеспечена) with evidence quote, gap, and a concrete fix. Each finding can be **«Оспорить»**-ed (Pro) — re-verified against its own cited content-section excerpts. **Раздел 13 «Образовательные технологии»** is checked the same way — declared teaching methods (кейс-метод, проблемное обучение, …) scored ONLY against СРС + control/ФОС content (never lectures/practicals/labs), catching a declared technology that never shows up in how independent work and assessment are actually run. Separately from coverage, the report flags «Знать/Уметь/Владеть» lines that merely restate a competency indicator verbatim — a real defect a методист caught the check scoring as 100% «Обеспечена»: a ЗУВ formulation must convey the indicator's meaning through the discipline's own content, not copy its wording. Detected deterministically (no model call — a copy is a measurable string question), shown with the ЗУВ line and the indicator side by side so the duplication is visible rather than asserted, and carried into the verdict line so a copy-pasted РПД can't read as «полностью обеспечивает».
- **РПД-студия** (T5) — select a discipline → AI drafts РПД content (цели, результаты по компетенциям, темы, формы контроля) aimed at its ОПК/ПК/УК + goals, then self-checks coverage. Sections editable; «Перепроверить покрытие» re-scores the edited text (write→check→fix loop). AI assists; teacher is author of record
**Материалы (хаб генерации)** — single sidebar entry (`/materials`) that launches all generators below (Презентации / Тесты / Темы работ / Задания / Кейсы / Проекты), replacing separate menu items; clear "what can I create?" overview for new users
**Задания студентам** — срок сдачи (дата и время) задаётся прямо в задании; студентов можно добавить группой — вставить список по одному имени в строке, каждый получает свою персональную ссылку, — и скопировать все ссылки разом (имя + ссылка на строку) для рассылки или таблицы. **Задания / Кейсы / Проекты** — one practical-material generator (`/materials/:kind`): topic + difficulty (базовый/средний/продвинутый) + optional subject → задания (условие), кейсы (ситуация + вопросы для разбора), or проекты (цель, результат, этапы), each with developed skills and a teacher hint. Copy-all + per-kind history. Free: 3/mo, Pro: unlimited
**Presentations** — slide-by-slide generator with typed layouts (title, понятие, формула с KaTeX, сравнение, схема, обсуждение, итоги — модель выбирает тип под содержание) + спикерские заметки, copy-per-slide. Optional conspectus (up to 20k chars, same priority-over-RAG precedent as Quizzes) builds the deck strictly from the teacher's own notes instead of inventing content from the topic alone — pasted directly, or uploaded as a PDF/Word file (`Загрузить файл`), which also recovers Word equation objects as LaTeX (paste alone can't — a Word equation has no plain-text clipboard form and just vanishes; PDF stays plain-text-only, since PDF math is usually drawn glyphs, not extractable). A .docx that is really just pasted screenshots of a textbook is OCRed automatically, so a "text-free" conspectus still supplies real material instead of leaving the model to invent the lecture from the topic alone. **«Строго по конспекту»** checkbox — when ticked, the deck contains only what the conspectus already says (no invented definitions, examples or numbers; a thin conspectus yields fewer slides rather than padded ones). **Real PPTX export** (Pro+) — `Скачать PPTX` downloads a native, editable PowerPoint (branded layout per slide type, formulas rendered as images matching the KaTeX web viewer — falls back to readable-Unicode text only if rendering fails for a given formula — images embedded for all slide types — diagram images full-width, non-diagram images as a right-column side panel alongside the text). Generation runs as an async queued job (survives HTTP timeouts / handles concurrent load) via an outline+parallel-expansion pipeline (each slide gets its own full writing pass instead of splitting one shared budget) with a **depth selector** — «Стандартная» (every tier, ~1min30s of speaker notes/slide) vs «Углублённая» (Pro+, longer/more detailed notes). **План лекции перед генерацией** — на «Построить план лекции» ИСПУМ за несколько секунд возвращает структуру (порядок, тип и краткое ТЗ каждого слайда), которую можно отредактировать — поменять порядок, тип, заголовок, добавить или удалить слайд — и только потом нажать «Написать слайды»: правка структуры до генерации стоит секунды, после — полной перегенерации. Включено по умолчанию, отключается галочкой «Показать план лекции перед генерацией». **Раздатка для студентов** — PDF по лекции: слайды и заметки докладчика как связный конспект, либо тот же материал без конспекта — скелет, по которому студенты пишут сами. **Письменная работа по вопросам лекции** — слайды «Обсуждение» превращаются в задание (без подсказок-направлений ответа, которые остаются у преподавателя), дальше — обычный поток опубликованных заданий. **Правка тематического плана** — разбор РПД делает ИСПУМ и иногда ошибается в таблице программы; план можно поправить руками («Править план»): переименовать тему, поменять порядок, удалить, добавить — или ввести план целиком вручную, если РПД не загружена. **Тема из рабочей программы** — тематический план один раз разбирается из РПД предмета («Разобрать РПД»), после чего тему и номер лекции можно выбрать из списка, а не вводить руками; содержание темы из РПД становится заданием для генерации, и готовая лекция остаётся связанной с темой программы (материал для УМК). **«Проверить усвоение»** — по готовой лекции одной кнопкой составляется тест (5–20 вопросов, уровень по Блуму) — не по теме вообще, а по слайдам и заметкам докладчика именно этой лекции — и сразу запускается в аудитории через живой QR-тест: студенты отвечают с телефонов, результаты сохраняются в журнал. Тест расходует лимит тестов, а не презентаций; удаление презентации не удаляет созданный по ней тест. **Фирменный стиль** — вуз задаёт акцентный цвет и логотип («Фирменный стиль» в админке учебного заведения), и все презентации, которые преподаватели выгружают в PowerPoint, оформляются в нём: цвет на слайдах, логотип и название вуза на титульном листе. **«Написать заметки»** — к загруженной презентации ИСПУМ пишет заметки докладчика для слайдов, у которых их нет; сами слайды не меняются. Расходует одну генерацию из месячного лимита. **«Загрузить свою презентацию»** — .pptx разбирается по слайдам вместе с заметками докладчика и становится обычной лекцией ИСПУМ: слайды можно переписывать, по ней составляется тест, раздатка и письменная работа. Бесплатно, без расхода лимита генераций. **«Много текста»** — слайды, которые не поместятся на проектор (16:9), помечаются прямо в просмотре, до выгрузки в PowerPoint. **Банк лекций кафедры** — готовую лекцию можно положить в общий банк кафедры (нужны права УМУ): коллеги увидят её в разделе «Лекции кафедры» и смогут открыть, а ИСПУМ будет ориентироваться на неё при подготовке их лекций. Лекция коллеги открывается только для просмотра. Видимость ограничена своей кафедрой (и подразделениями под ней) — не всем вузом. **«Готово» — ИСПУМ учится вашему стилю** — отметьте удачную лекцию, и следующие будут писаться с оглядкой на неё: глубину заметок, формулировки, манеру. Берётся именно стиль, а не содержание, и только из ваших собственных отмеченных лекций — ничего не передаётся коллегам. Отметку можно снять. **Правка готовой презентации** — каждый слайд можно отредактировать вручную (заголовок, содержание, заметки докладчика), переписать силами ИСПУМ по замечанию («короче», «добавь пример с числами» — переписывается только этот слайд, остальные не трогаются), удалить, переставить выше/ниже или добавить новый: раньше одна неудачная страница означала перегенерацию всей презентации или уход в PowerPoint. Правки не расходуют месячный лимит — он считает презентации, а не изменения в уже созданной. **Web-search grounding** automatically activates when there's no pasted text and no RAG material (Yandex Web Search — top 5 results injected into both the outline and expansion passes; fail-open if search is unavailable). **Images auto-search during generation** (Yandex Images, ranked — small/stock results deprioritised) for any slide type the model judges needs one, not just diagram slides; any slide can also have an image manually added via «+ Добавить изображение» — swappable via the same picker
**Quizzes («Тесты»)** — 5–20 multiple-choice questions on a topic, at one of three Bloom-style levels (recall / understanding / application), grounded in the subject's materials via RAG with source citations, or in a pasted lecture-notes text (up to 20k chars) instead — pasted notes take priority over RAG retrieval and skip source citations. Answer reveal, history. Free: 3/mo, Pro: unlimited
**Live QR quiz («Запустить в аудитории»)** 🚧 — run any generated test live in the lecture hall, in either of two pacing modes chosen at launch: **«В темпе группы»** — a chrome-free projector screen (`/live/host/:id`) shows a join code + QR and, per question, a live answer histogram, teacher-paced through show-answer/next-question; or **«В своём темпе»** — each participant moves through the quiz independently (a «Далее» button on their own reveal screen), with the projector showing a live per-participant progress roster instead of a shared histogram. ## Head of an educational programme (РОП) ✅

A teacher granted `head` on a `program` or `program_direction` org_unit sees **«Образовательные программы»** (`/programs`) filtered to their programme(s) only, with full read + edit rights. Programmes are grouped by направление in the list — a направление with several профилей collapses into one heading + nested cards. Imports their own ОП via the intake form (описание ОП + учебный план PDF); the picker (now first in the form) pre-selects when they head exactly one unit and forces a choice when they head several, prefixing each option with `ОП: ` or `Направление: ` so the linked level is unambiguous. **Picking the unit auto-fills the ФГОС header** (код, наименование направления, уровень, формы обучения) from metadata the admin recorded on that unit — уровень is a dropdown and формы are checkboxes (national-standard sets), профиль stays the РОП's to enter. Non-clickable breadcrumb on the detail page shows the ancestor chain of the linked unit so the РОП sees which институт their programme sits under.

Per-programme surfaces on the detail page:
- **Конструктор** — edit the extracted disciplines and competencies by semester. Каждая **ПК**-компетенция (unlike УК/ОПК, which come verbatim from the ФГОС) can be linked to the specific **профстандарт → ОТФ** (обобщённая трудовая функция) it was derived from — a cascading picker scoped to the programme's own направление, flagging any ОТФ whose «требования к образованию» don't match the programme's level (бакалавриат vs магистратура pick different ОТФ rows on the same профстандарт) — plus an indicator editor (ПК-1.1/.2/.3). Once linked, a deterministic check (no LLM — same discipline as the ЗУВ-copy check above) flags a ПК/indicator formulation that merely restates the ОТФ verbatim instead of conveying its meaning, shown inline under the competency and rolled into the Отчёт tab's whole-programme analysis. Профстандарт/ОТФ data itself is a platform-admin-curated registry (`/admin/profstandards`, mirrors the ФГОС registry — upload/extract → review → publish).
- **Отчёт (analysis)** — headline **«Достижение результатов программы»** (does the whole plan deliver the graduate profile: verdict обеспечены / частично / есть пробелы + delivery score + covered/thin/late/uncovered breakdown, rolled up from the competency progression); sequencing & prerequisites (incl. a **holistic «Дерево зависимостей»**: dependency layers foundational→профильные, key prerequisite chains, isolated disciplines — whole-plan view derived from the edges), competency progression map, gaps & redundancy, relatedness clusters + per-semester load. Cached; last analysis exportable as a branded PDF.
- **Документы** — per-discipline РПД library. Every discipline gets its own upload slot; on upload we extract the text and **auto-detect which competency codes the РПД declares** (filtered against the programme's own competency set), pre-populating `competency_codes` so «Проверить соответствие компетенциям» works without a конструктор detour. The check scores the РПД at the **индикатор level** — each competency is decomposed into its индикаторы достижения (ОПК-14.1/.2/.3) with their Знать/Уметь/Владеть layer, each scored against the discipline content (лекции/практ/лаб/СРС/ФОС) with an evidence quote + note; the competency's covered/partial/missing status is the roll-up of its indicators, so «частично» shows exactly which indicator is the gap. Indicators render nested under each competency inline in the row (also mirrored in the Report tab). Each discipline with an uploaded РПД also offers **«Открыть в РПД-студии»** — a bridge that find-or-creates the caller's personal предмет (name-matched case-insensitively so repeat clicks reuse it; syllabus seeded from the РПД's extracted text, never overwriting a предмет that already has one) and deep-links to `/curriculum?tab=studio&course=<id>`, closing the gap between the programme document library and the teacher-scoped студия. Практики stay programme-scoped (fixed 4-type set). A discipline's РПД history is now retained across re-uploads instead of being discarded — once a discipline has ≥2 uploaded versions, **«Что изменилось с прошлого года»** compares the current file against the one it replaced and reports a structured diff (changed topics, changed competency mappings, changed forms of assessment), not a text diff. Every programme-document uploader (РПД, practices) also accepts a **pasted link** to the file in the institution's own university web system instead of a download+re-upload — the server fetches it, restricted to a **per-institution domain allowlist the institution admin manages** on the org overview page (`institutions.document_fetch_domains`; subdomains of a listed host are allowed, so `kstu.ru` covers `www.kstu.ru`), plus an optional global env supplement. Independently of the allowlist, the fetch **refuses any URL that resolves to a private/internal address** (SSRF guard with connection pinning against DNS rebinding), so even a compromised admin can't turn it into an internal-network probe. On top of the per-link pull, **«Импортировать со страницы сведений»** does the whole set at once: paste one link to the university's mandated «Сведения об образовательной организации → Образование» page (`/sveden/education`) → the Рособрнадзор-required `itemprop` microdata table is parsed (text-keyword fallbacks for imperfect markup; аннотации, whose links carry identical discipline names, are excluded via the cell markup), the programme's row is found by направление code, РПД links auto-match to disciplines by normalized/fuzzy name (below-threshold → manual dropdown, never a guess), практики get type suggestions only on unambiguous keywords — then the РОП confirms a checklist and every confirmed document imports through the same fetch pipeline sequentially with live progress; items that would replace an existing file default to unchecked.

The tool is analysis-only — programme content is authored in the university's own system; here we ingest, correct extracted content, and analyse.
